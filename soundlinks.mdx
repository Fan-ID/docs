Use the Soundlinks API for soundlinks **without** a Soundlink-funded campaign. Those soundlinks do not appear in `GET /v1/campaigns`. For paid campaigns, use [Syncing campaigns](/syncing-campaigns) instead.

Requires `soundlinks:read`. See [Authentication](/authentication#scopes-v1).

<Note>
  Existing API keys keep the scopes they were minted with. Create a **new** key and add `soundlinks:read` to call these routes.
</Note>

Campaign-linked soundlinks are the campaign's underlying resource. List and detail them with the Campaigns API. A campaign-backed `soundlinkId` on these routes returns `404`. Missing `soundlinks:read` returns `403 insufficient_scope`. See [Errors](/errors) for the full list.

## List soundlinks

`GET /v1/soundlinks`

Supports pagination:

| Param | Default | Max |
|-------|---------|-----|
| `page` | 1 | — |
| `pageSize` | 10 | 100 |

`sortBy` is `createdAt`. `soundlinkId` is a URL-safe string — the same ID in the public `sndl.ink` URL — not a campaign UUID.

```bash
curl -sS 'https://api.getsoundlink.com/v1/soundlinks?page=1&pageSize=100' \
  -H 'Authorization: Bearer sk_YOUR_PREFIX_YOUR_SECRET'
```

Walk pages until `pagination.page >= pagination.totalPages`.

## Soundlink detail

`GET /v1/soundlinks/{soundlinkId}`

Returns catalog fields plus `autoFollow`, `metaPixelId`, and `tiktokPixelId`. Unknown, cross-org, or campaign-linked IDs return `404`.

Use the `soundlinkId` from the list response in all `/metrics/*` paths.

## Which metrics endpoint

Soundlink metrics omit spend, fees, and efficiency fields (`cpl`, `cpf`) — ads run in your Meta account. There is no JSONL export or country breakdown.

| Use | Endpoint | Maps to Insights |
|------|----------|------------------|
| Period totals | `/metrics/overview` | **Overview** |
| Per-day rows | `/metrics/timeseries` | **Trends** |
| Per-track period totals | `/metrics/engagement` | **Overview** tracks |

On overview and timeseries, `startDate` and `endDate` are inclusive (`YYYY-MM-DD`). They default to the soundlink creation date and today.

Engagement does **not** use that default. It snaps to the Insights windows: yesterday, the last 7 days ending today, or all-time. Omit `startDate` for all-time — that is not the soundlink creation date. An arbitrary range such as a calendar month snaps to all-time.

## Overview

`GET /v1/soundlinks/{soundlinkId}/metrics/overview`

Period totals only — no per-day rows. Use timeseries for those.

Fields include `views`, `link_clicks` (nullable), `streams`, `listeners`, new/returning listener and stream splits, `followers`, `streams_per_listener`, and `ctr_lp`.

```bash
curl -sS 'https://api.getsoundlink.com/v1/soundlinks/{soundlinkId}/metrics/overview?startDate=2026-08-01&endDate=2026-08-31' \
  -H 'Authorization: Bearer sk_YOUR_PREFIX_YOUR_SECRET'
```

## Timeseries

`GET /v1/soundlinks/{soundlinkId}/metrics/timeseries`

Paginated per-day rows (`soundlink_daily` v1.0). One row per `report_date`. Rows are aggregated across countries — there is no `country_code`. Default `pageSize` is 50 (max 500). Sort is `report_date`.

Primary key:

`(provider, account_id, report_date, soundlink_id)`

Re-ingest on that key is idempotent. Rows for a given `report_date` can change for up to **7 days** after the date closes (delayed Spotify events). Re-fetch and upsert.

Do not sum `listeners` across days — the same listener can appear on multiple `report_date` rows.

```bash
curl -sS 'https://api.getsoundlink.com/v1/soundlinks/{soundlinkId}/metrics/timeseries?startDate=2026-08-01&endDate=2026-08-31&page=1&pageSize=50' \
  -H 'Authorization: Bearer sk_YOUR_PREFIX_YOUR_SECRET'
```

## Engagement

`GET /v1/soundlinks/{soundlinkId}/metrics/engagement`

Paginated period totals per track — not daily rows, and not the campaign JSONL engagement export. Sort by `totalStreams` (default) or `totalListeners`.

Each item includes `trackId`, `trackName`, `totalStreams`, `totalListeners`, and `streamsPerListener`. There is no `playlist_position` on this endpoint.

Omit `startDate` (and `endDate`) for all-time. Pass a single UTC day of yesterday for yesterday, or an inclusive 7-day span whose `endDate` is today for last 7 days. Other ranges snap to all-time.

```bash
curl -sS 'https://api.getsoundlink.com/v1/soundlinks/{soundlinkId}/metrics/engagement?page=1&pageSize=100' \
  -H 'Authorization: Bearer sk_YOUR_PREFIX_YOUR_SECRET'
```

## Typical sync flow

1. **Daily:** `GET /v1/soundlinks` — upsert catalog
2. **Daily:** overview and/or timeseries
3. **Optional:** engagement (yesterday, last 7 days, or all-time — not the overview/timeseries date range)

Your organization comes from the API key only. Do not pass `organization_id`. Timeseries rows include `account_id` for your org.
